## Minimal unchanged-model contract

For `BoneSplitMode::Translate` (wire1), require a nonempty TranslateX track; allow
TranslateY to be absent or nonempty. An explicitly stored empty Y timeline is
still invalid; represent absence by no timeline. Preserve every row, order, bone
identity/inlining, X key/curve f32bits, existing layout, string aliases and unrelated
fields. Do not create a Y key during decode/normalize/Save or drop mode1 because
Y is absent. Existing combined canonical payloads remain unchanged.

Mode2/Scale still requires both nonempty axes. Reject Y-only Translate, no-X/no-Y
mode1, incomplete Scale, scalar channels without a matching mode, duplicate or
foreign rows, unknown3/combinations and combined/split-family collisions. Existing
finite values, scalar padding, depth/arena/budget, exact monotone-time and full
payload equality guards remain in force. The only format change is the known
Translate completeness predicate, plus focused tests; do not loosen generic
parser/schema or model types to fit E.

**FBones authoring policy:** on an existing mode1/X-nonempty configuration, an
addressed Y key may create the missing Y timeline. Deleting the last Y key removes
that timeline and retains mode1+X; deleting the last X key rejects atomically,
including a batch that would leave Y-only or both absent. Bone deletion keeps
its existing dangling-reference rejection: `scene_bridge::remap_bones` maps every
retained track through a fallible identity lookup before mode-row cleanup, so a
keyed deleted bone rejects atomically rather than dropping tracks. Surviving
configuration rows retain their order/remapped identity. No new bone-deletion
behavior is authorized. No automatic representation conversion or implicit new split-mode creation is
introduced. Y creation/deletion updates existing semantic wire layout and stable
key IDs through the same native reconciliation policy; no fabricated replacement
keys or unrelated X edits occur.

Before a Y timeline exists, expose its empty scalar row only as the UI's declared
policy; its live value is Setup-relative Y0. Shared-family manual Key may explicitly
key both axes; axis-row Key/dirty K/AutoKey address only intended physical axes.
X-only key publication must preserve an unkeyed/newer Y working intent, and Y
publication must not consume X intent. Existing source-relative scale and all
nonbone/other-mode paths retain their current behavior.
