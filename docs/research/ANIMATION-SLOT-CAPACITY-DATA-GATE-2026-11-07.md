## Coherent bounded policy

Propose exported `MAX_SCENE_SLOTS = 512` for Scene inventory and full draw-order
permutations/offsets only. Legacy Region/Mesh slot inventory stays128, including
Scene-to-legacy conversion and legacy encode/decode. Image placement remains
1…128 items per command, while adding slots may reach512 total; adding alternative
attachments consumes no new slot. Keep attachments512 total, constraints128,
binding/member128, Scene bones256, geometry4096, Mesh512/Clip256, PNG/cache/file,
all-family1024 clip tracks/4096 project tracks/8192 keys, generic/domain/depth and
all other existing independent guards. Slots may be empty and have null active
references; never invent an attachment or drop an inactive alternative to fit.

Current format boundaries are `scene/validate.rs` slots128 and
`scene/deform.rs` permutation/offset helpers128. The initial ignored prototype
changing only these three sites failed at encode/reopen closure for265 reversed
slots. A fourth known boundary is reader class205's draw-offset count128, used by
kind13 keyframes. Its Scene limit must also be512, with legacy policy retained.
GenericArray15 already permits512, ShortList/IntList4096 and signed offsets are
wide enough; no general parser-array/list expansion is needed. Keep complete
reserialization equality, exact raw offset record order (including explicit
identity records), cached reference identity and all existing structural closure.
The existing authoring helper's minimal-offset choice remains an FBones policy.

Native `scene_edit::AddImages`, `Session` image placement and any legacy route
must distinguish128-command count from512 Scene inventory. Stable slot IDs,
Setup slot reorder, active/alternative attachment references, Clip endpoints,
attachment order, slot/Sequence/deform/constraint ownership, dark/color tables,
wire alias/layout metadata and draw-order keys must remap together. Existing
keyed-slot deletion policy must remain explicit and atomic. No silent dropping,
index reuse, overflow/truncation or weakened stale-resource/frozen-pose guards.
Order APIs still require each current stable slot ID exactly once; Setup reset
is distinct from an authored literal permutation. Sampling must handle Setup,
before-first-key, empty-offset reset and high-index keyed permutations alike.
