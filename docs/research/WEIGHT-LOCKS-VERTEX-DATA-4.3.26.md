## Read-only source gap and own policy proposal

Current `mesh::add_vertex` creates zero positions then calls `set_vertex`, which
sets every zero-weight column to0,0. `mesh_edit::remesh` only interpolates a
column's local coordinates when its new weight exceeds an epsilon;
`clip_edit::insert_vertex` similarly leaves dormant columns zero. Typed Auto/
manual operations correctly preserve all existing positions, so later assigning
weight to these new dormant columns can move a vertex to a bone origin.

**Proposal, not recovered original behavior:** for insertion inside an old face
or edge, use the weighted barycentric local-coordinate quotient for positive
weights. For a new zero-weight column, interpolate the old local-coordinate
field with ordinary barycentric coefficients, retaining the old bind-offset
field rather than inventing a new current-pose binding. Preserve every old row
bit for bit, including legitimate zeros. Outside the old hull, choose and record
a separate bounded extension policy; current-world inverse initialization and
per-column plane extrapolation are distinct choices, neither proven original.

This proposal requires coordinator approval and independent FBones geometry/
failure/history/save tests before implementation. It does not justify an
original insertion parity claim. The five numeric contracts above are ready
for dependent review; brush behavior uses the explicit bounded policy above.
No production code changed for this memo.

## Independent approved-policy math review

The coordinator's later approved outside/off-edge policy is now recorded in
`WEIGHTED-VERTEX-BINDING-POLICY.md`: clone the complete nearest row, then move
every column by its bone's inverse **vector** applied to
`(target-currentWorld)/sumWeights`. This includes dormant columns. For a fixed
bone matrix, projecting that local vector adds the same world delta to each
column; summing weighted columns therefore produces the requested movement.
Using an inverse point would subtract bone translation again and would be wrong.
A nonzero extension requires every bound inverse, including dormant columns;
any required singular inverse fails atomically. Zero extension needs none.

For interior interpolation, multiplying each new positive coordinate quotient
by its new weight cancels the denominator, reproducing the barycentric sum of
old weighted world positions. Ordinary zero-column interpolation carries the
old dormant local field independently. A small positive-only correction may
absorb f32 normalization error without rebasing the dormant field. This review
supports the stated **FBones design**, not original insertion parity.

Meaningful checks should distinguish the quotient from naive interpolation and
current-pose rebinding; activate dormant columns afterward; test reflected/
noncoincident fields, tiny positive weights below the former epsilon, old signed
zeros through hull reorder, interior dormant singular poses, nonzero outside
singular atomic failure and zero-extension inverse avoidance. Local coordinates
need finiteness; the authored target's world bound must not be confused with a
new arbitrary bound on legitimate large local positions under small scales.
