# PSD layer import: DATA gate before implementation

The user requests Photoshop PSD import preserving layer positions and depth order. This is the next authorized feature after native-upgrade/CI closeout, not resumed Physics/Match final100% work. No original editor launch or completed reference batch is needed for this bounded implementation.

**Evidence.** Existing exact4.3.26 [mascot metadata](MASCOT-SUPPORT-DATA-GATE-2026-11-08.md) proves passive source149/history importPsdFile records only; its PSD-like path does not establish an import gesture, coordinate origin, layer ordering or rendering algorithm. Preserve that metadata passively and do not populate speculative original fields for this feature. Existing typed Region/slot/image persistence is reusable; this new operation is an explicit **FBones import policy**, not claimed Photoshop/Spine PSD parity.

The primary [Adobe PSD specification](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/) documents version1, channel/depth/color-mode declarations, signed layer rectangles in top/left/bottom/right form, separate channel bytes/transparency, opacity, blend/clipping flags, names including Unicode luni, and grouping via section dividers. Its compression identifiers distinguish raw, RLE and ZIP. These are container facts, not exact4.3.26 behavior. File-record order must be checked in the chosen decoder rather than confused with a UI collection's order; normalize the parser result explicitly to bottom→top. Use own overlapping-color fixtures to establish actual ordering and visibility flag polarity (`0x02` hidden), not the ambiguous label of the visibility bit alone.

**Usable90 profile.** Accept PSDv1, RGB,8 bits/channel, flat ordinary raster layers, normal blend, raw or PackBits channel compression. Support RGB plus optional straight transparency; retain per-layer opacity separately. Reject PSB, unsupported depth/mode/compression, groups, masks/vector masks, clipping, effects, text, smart objects, adjustment/fill layers and other appearance-changing records before scene/resource mutation. Never silently import a composite preview or drop unsupported effects. Zero-area empty layers may be skipped with an explicit count/warning; require at least one supported nonempty layer. Keep hidden nonempty layers as inventory/slots with no active attachment, so they can be shown later. Alpha0 opacity is not the same as hidden. Preserve source names as bounded display names, with deterministic unique names where needed; generate independent portable collision-safe PNG keys, never paths derived verbatim from PSD names.

**Coordinates/order.** Import into the current editable Setup document under one chosen bone. The PSD canvas center maps to that bone's local origin; one pixel equals one authoring unit in that local space. For document W,H and layer L,T,R,B, use local center `x=(L+R-W)/2`, `y=(H-T-B)/2`, dimensions `R-L,B-T`, rotation0/scales1. Keep fractional half-pixel centers and signed off-canvas bounds; do not independently center, grid-pack, sort by name or trim each layer. All layers inherit the same destination-bone affine transform, including rotation/reflection/nonuniform scale; this preserves the local collage and does not claim world-pixel size under a transformed bone. Existing AddImages converts world centers only while leaving attachment axes local: either stage these local centers directly or supply their authored-bone transformed centers deliberately. Do not invert only the centers and claim world-axis parity. Do not sample/bake Physics or animation.

Create one independent slot plus one Region attachment per retained raster layer, appended as one contiguous block in normalized bottom→top order; existing content remains behind that new block. FBones renders slots in order and hit-tests in reverse (`src/domain/images.ts`, `src/viewport/ImageLayer.ts`). There is no invented z-coordinate. Retain hidden-layer ordering, set slot activation from visibility, slot RGB white/alpha equal to the opacity byte, and keep channel alpha unmodified to avoid applying opacity twice. Region name, asset key and slot identity are distinct. Existing slot-order animation references must retain their identities after the structural append.

**Atomic native/persistence contract.** Reuse `ImageAsset`, `ImageCache`, typed `SceneRigHistory` and the existing binary encoder/PNG save bundle. Read/validate the complete bounded input and every decoded layer/PNG before taking the commit lock; require the expected revision and an editable supported document/bone at commit. Stage the cache and the entire typed scene in clones; validate encoder/history/remaps before publishing either. One import yields one revision/Undo action; Undo removes the whole imported block and Redo restores exact IDs/order/positions/activation/opacity. Failure/staleness/cancel cannot consume IDs, history, dirty state or partial resources. Immutable cached PNGs may remain available for Redo; account for their cache budget rather than writing them beside the PSD.

Current `prepare_save` writes cached PNGs only for managed image roots (`./images/`, `images/`, `images`). Therefore90 import rejects an external/nonmanaged root with actionable **Save As into a portable project first** guidance; no silent rebase or memory-only success followed by missing-file reopen. Normal Save/Save As retains existing collision/symlink/regular-file checks, writes validated PNG resources before atomic project replacement and marks clean only after success. The resource bundle is not a global filesystem transaction: harmless newly written PNGs may remain if a later project write fails, while the project remains dirty. Never overwrite the PSD, original .spine, external source folders or unrelated files. No PSD is required to reopen the saved project.

**Bounds and verification.** Initial parser read cap64MiB, at most128 imported layers, each decoded image within existing4096-side/64MiB limits, checked section/channel lengths, exact row decompression and a declared aggregate decoded-byte budget before allocations. Keep existing cache128MiB PNG/256MiB decoded and scene512-slot bounds; reject a batch that exceeds remaining capacity. Required own fixture: unequal canvas/layer bounds, overlap colors proving front/back, odd centers, off-canvas layer, Unicode/duplicate names, opacity128 and hidden layer. For W100,H80 and L20,T10,R40,B30, expected local center(-20,20), size20×20. Verify raw/RLE equivalence, malformed/unsupported rejection, transformed-parent local collage, stale/full-cache/full-slot rejection without mutations, one Undo/Redo, native Save/Close/Open plus independent binary order/geometry/color/activation and PNG hashes. Existing scene/animation/resource regressions remain coordinator-owned. Original PSD import parity, groups/effects/color-management and broader codecs remain explicit later scope, not implied by this slice.
