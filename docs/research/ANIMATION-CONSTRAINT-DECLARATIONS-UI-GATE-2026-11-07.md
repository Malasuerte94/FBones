## Persistence-only FBones policy

Preserve proven source type-specific declaration inventories as typed validated
serialization provenance. Do not reorder the UI, `SceneProject.constraints`,
solver execution/prefix, constraints on a bone, or timeline rows to make payload
equality pass. No new declaration-order list/toggle/control is justified.
New canonical files and old own files must keep their current canonical bytes.

Unrelated edits, parameter changes, rename and key changes keep surviving source
declaration identities/order. An explicit execution reorder changes the ordered
runtime/UI vector, while declaration provenance follows those stable identities
without silently sorting itself into the new execution order. This policy changes
no solver arithmetic or original gesture claim. Native structural reconciliation
must map provenance by old/new semantic IDs, not reuse stale vector indexes.

Deletion prunes the addressed declaration; creation adds its genuinely new
same-kind declaration by an explicit deterministic canonical append policy, unless
DATA establishes a narrower original rule. Validate exact membership/kind/no
duplicates before publication. Unknown type-conversion/alias patterns must reject
rather than relocate records by name. Rename must not confuse equal names with
identity; delete/recreate must not inherit the old object's metadata. Undo/Redo
restores both authored execution order and full provenance in the same frame.
IK or other untouched declaration families must keep their prior behavior.

For a first execution reorder from canonical `wire=None`, derive declaration
order from the BEFORE identities and preserve the complete existing canonical
string aliases/layout/scalars when materializing provenance. An empty synthetic
wire wrapper would change old default label sharing; do not use it. A bounded
codec-owned capture helper may establish known typed provenance and exact bytes
once for that completed action, while the per-frame preview path remains intact.

Save/Save As/resource summaries use their existing routes. Save still waits for
pending edits and existing invalid/stale guards; portable resource-root rebasing
must preserve unrelated declaration order across current and history frames.
No new full-scene IPC, timer, evaluation, Physics clock, freeze lease or authoring
action is introduced by serialization metadata. Simulate off and unkeyed drafts
retain their established policies. No post-write normalization may create a late
failure after a target has already been changed.
