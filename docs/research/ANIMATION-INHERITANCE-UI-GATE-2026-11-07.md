## Existing UI and editing ramifications

Current `BoneView` and native bone DTO have no inheritance field. BoneInspector
has Setup name/parent/color controls; the shared HUD edits physical local fields
in Setup and sampled pose/keys in Animate. A future supported mode must not be
lost when the field editor spreads a bone into a native Update or the native
handler reconstructs a bone. No inheritance timeline/key channel is authorized
by the observed Setup values. Full-summary authored resource continuity must
continue comparing the typed mode without a special relaxation.

Current `domain/rig.ts::worldBones`, `solve/math.ts::recompute` and native worlds
compose the full parent affine with the local affine. The evaluated-world
override can display one known result but cannot fix subsequent live local edits,
inverse math or native constraints. `previewTransformBones`, move/tip/length,
solver setWorld, IK/Transform/Physics stages and native `set_pose` use the normal
parent/inverse basis. Mesh/Clip skinning, attachment transforms/Fit/picking and
frozen geometry depend on those same worlds. A mode can affect a basis and
translation differently; simply skipping parent composition is not a supported
implementation rule.

Native Reparent and group parenting preserve world pose by converting through
the new parent's inverse and rebuilding local rotation/scale/shear, then remap
stable source identities. Nondefault modes require their own forward/inverse
contract, singular rejection and local-branch policy before these tools can be
called correct. A working import-only affine sample would not prove viewport
drag, reparent, weighted binding, constraint writes or animation Auto Key.
Do not rerun deferred Match/Physics fidelity probes merely to explore this enum;
retain the existing normal-inheritance checks and isolate any required new case.

Keep the shared HUD and all panel placement unchanged. Once mode semantics are
established, Setup-only inheritance status/controls belong in the existing bone
inspector, using compact labeled controls and textual state rather than color
alone. Do not add apparently active Rotation/Scale/Reflection toggles with guessed
dependencies. Preserving/rendering a proven imported mode and authoring a toggle
are separable claims; a clearly read-only imported status could be an explicit
FBones policy, but no such product slice is authorized by this research gate.
