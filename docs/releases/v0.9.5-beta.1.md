## Application updates

**Install 0.9.5 once to enable future updates.** Earlier 0.9.4 copies have no
updater and cannot acquire it from a GitHub release alone. An updater-enabled
packaged app checks for a newer version and downloads it in the background;
installation/restart is explicit. Automatic checks can be disabled, and manual
checking remains available. Offline failures leave the editor usable.

Installing first flushes valid fields and protects unsaved work through
Save/Discard/Cancel. Invalid edits, failed or canceled saves and active operations
cannot silently lose a project. Download completion means the update is ready,
not installed. Portable development/workspace copies cannot replace themselves.

The release's `latest.json` contains distinct Windows NSIS, Linux Debian and
AppImage routes and universal macOS routes for both architectures. Every update
requires the pinned public key, valid package signatures and an authenticated
application version. Future publications must increase the real app version;
changing only a beta tag does not update a client already running that version.
See the [update policy](https://github.com/Malasuerte94/FBones/blob/v0.9.5-beta.1/docs/UPDATES.md).

## Constraint selection and shared editing

Constraint rows now have distinct IK, Transform and Physics icons. Ctrl/Cmd and
Shift select multiple constraints; a same-type group exposes shared fields and
shows mixed authored values explicitly. A completed shared edit is atomic and
creates one Undo action. Mixed types remain read-only.

Setup supports shared Physics fields/global flags, IK mix/softness/bend/compress/
stretch, and Transform mixes/offsets/space/additive/clamp. Supported Animate
fields use the existing pose drafts or one combined key operation: Physics's
seven dynamic coefficients, IK mix/softness/flags and Transform mixes. Names,
bone references, order, Match and group deletion are outside the shared-field
operation. These are FBones interaction policies; no new original-Spine gesture
or numeric parity claim is made.

## Developer runtime

The independent MIT package contains FBones code with no Spine runtime dependency.
Download the archive and install it in your game project:

```sh
npm install ./fbones-runtime-0.1.0-beta.1.tgz
```

Its Node/browser player is headless; `/pixi` adds an optional PixiJS 8 view. The
editor's **File → Export runtime** creates a separate authored-data/resource
bundle. `.fbones` authoring remains binary. npm registry publication is not part
of this release. See the [runtime guide](https://github.com/Malasuerte94/FBones/blob/v0.9.5-beta.1/packages/runtime/README.md).

## Verification and limits

The tag workflow retains all three platform build/test jobs and the Ubuntu
production-CSP UI/runtime gates. Release assembly verifies exact source commit,
version, architectures, closed file inventories, payload hashes and updater
signatures, then publishes aggregate checksums including `latest.json`.
Beta6's previous 114 UI passes and other implementation results retain their
original checkpoint; they are not relabeled as this release's results. Current
tag outcomes and downloaded-asset verification remain pending until observed.

Full Spine 4.3.26 project/runtime compatibility remains open. Runtime mixing,
direct binary-project loading, texture atlases, arbitrary skins/inheritance,
Path constraints and complete original numerical/Physics parity are not claimed.
Simulation is bounded to 120 seconds; unsupported documents stay guarded.
Native installation, hardware rendering, platform dialogs and macOS GUI behavior
are not established by package structures or browser tests.

This early beta is published in GitHub's **Latest** category for repository
visibility and the updater endpoint. Read the
[roadmap](https://github.com/Malasuerte94/FBones/blob/v0.9.5-beta.1/docs/ROADMAP.md)
and [checkpoint](https://github.com/Malasuerte94/FBones/blob/v0.9.5-beta.1/docs/STATE.md)
for the supported profile and remaining work.
