# FBones v0.9.4-beta.5

Animation reliability, playback efficiency, broader bounded project support and
the first independent FBones developer runtime. The editor's application version
remains **0.9.4**; the runtime package is **0.1.0-beta.1**.

This candidate follows the failed beta.3 and withheld beta.4 tags. The earlier
Windows test-loader file-URL correction and Sequence semantic no-op correction
remain included. The beta.4 tag run was intentionally canceled before release
publication after a newly reported native File menu defect was diagnosed. All
prior tags and evidence remain intact; no release gate is bypassed.

Native menu state updates now resolve existing command items inside the actual
File/Edit submenus. The former shallow root lookup missed them and left their
initial disabled state unchanged. Project capabilities and all authoring,
inspection-only, source-overwrite, validation and resource guards are unchanged.

The beta.4 hosted main run also reached a later Sequence Graph-key boundary:
Setup Undo/Redo passed, but leaving a committed key field resubmitted the same
key and consumed the next Undo click. The targeted key correction treats equal
mode/index/f32-delay as an unchanged pose while preserving the same controls,
validation and exact history assertions. The fresh local 114-case browser suite
passes both Sequence Undo boundaries; prior hosted failures remain recorded.

This prerelease prepares **source and a developer runtime archive**. No Windows,
macOS or Linux desktop installer is attached. The tag workflow publishes the
release only after the required platform, runtime and Ubuntu UI checks pass.
Build reports identify their exact source commit and package structure/hashes;
they do not establish native installation, hardware rendering or notarization.
An installed or running editor does not auto-update from this release.

## Changed

- Corrected native File/Edit menu state updates after New/Open/Close and edits.
  Supported documents can enable Save, Save As and runtime export; inspection
  documents retain their unchanged-copy capability while Save/export stay
  disabled. A document is still required, and existing command guards remain.
- Fixed Animate transforms moving again at mouse release. Frozen gestures now
  key the original gesture baseline instead of applying the preview delta twice.
  Signed X/Y movement, grouped transforms, Auto Key on/off, cancellation and
  one-action Undo/Redo remain covered.
- Fixed replacing precise numeric values after focus. Inputs retain exact text;
  compact presentation no longer destroys the existing text selection.
- Corrected Sequence Setup no-op detection. Equal settings with different JSON
  property order no longer start a redundant native edit when the field blurs.
  The same fields, validation, one-action history and exact test conditions remain.
- Corrected unchanged Sequence key submissions after Enter. Leaving an already
  accepted mode/index/delay value must not start another edit or consume Undo;
  equivalent f32 delay spellings retain their authored numeric meaning.
- Reduced playback work: affected-subtree constraint evaluation, one viewport
  submission per pose and cached unchanged timeline rows/Graph content.
- Retained the shared Setup/Animate transform layout, authored Setup data,
  native history, strict CSP and binary `.fbones` persistence guards.
- Expanded supported source structures with split Translate/Scale axes,
  X-only/default-Y preservation, linear two-color slot keys, portable Region/Mesh
  sequences, larger bounded Mesh/slot inventories and known typed source state.
  Unknown structures and reversing curves remain inspection-only.

Component CPU measurements on the retained mascot case show roughly 4× faster
constraint evaluation and 13.55× faster all-bone timeline custom-renderer work.
These are named component benchmarks, **not** a whole-app or Windows FPS promise.

## Independent developer runtime

`fbones-runtime-0.1.0-beta.1.tgz` is the installable MIT Node/browser package with
an optional PixiJS 8 entry. It contains FBones code and has no Spine runtime
dependency. The headless entry needs neither the editor nor Pixi.

```sh
npm install ./fbones-runtime-0.1.0-beta.1.tgz
```

The desktop's **File → Export runtime** creates a new bundle containing separate
`skeleton.fbones.runtime.json` game data and referenced PNG/WAV resources. It
preserves authored Setup and stored keys, rejects missing resources/stale
revisions/inspection-only sources and does not mark the project saved or bake
working poses. `.fbones` authoring files remain binary.

The declared profile covers bone channels and curves, slot activation/light/dark
color, weighted Mesh/Clip/deformation/draw order, sequences/events and the current
bounded FBones IK/Transform/Physics evaluator. Read the
[runtime guide](https://github.com/Malasuerte94/FBones/blob/v0.9.4-beta.5/packages/runtime/README.md)
for examples and limits. The npm registry name is not published by this release;
install its archive. Direct repository-root installation installs the editor.

## Verification and limits

Fresh local beta.5 checks pass 114/114 Ubuntu Chromium cases in 2.5 minutes with
no failures, skips or retries, under rebuilt production CSP and isolated real
Rust Sessions; 418 JavaScript tests pass with one existing skip. Runtime checks
pass 16 package tests and 24 native-export samples (maximum matrix residual
6.36e-7). Prior named checks retain 326 native/95 legacy passes with existing
ignored cases, 16 default-format/103 Scene-format passes, offline standalone
Node/strict TypeScript installation and shipped-Pixi WebGL pixel/ownership proof.
These local results do not establish fresh hosted CI acceptance. Beta.5 push and
CI remain pending at this checkpoint; exact tag jobs govern publication.

Own Windows native-menu QA passes six groups on an immutable test image: actual
WinAPI File items disabled when blank, all three enabled for an editable input,
native Save As and Export commands reaching OS pickers and producing correct
outputs, inspection-only Save As preserving identical bytes while Save/export
stay disabled, and Close restoring disabled state. Runtime JSON matches exact
typed-f32 values and export preserves authoring. Copying an inspection document
advances the Session revision once under the existing copy policy. The owned QA
closed normally; earlier caption/revision assertion failures remain retained.
The user separately tested the actual mascot and confirmed runtime export and
the other File buttons work. This confirms those commands for that user case;
it does not establish full project/runtime compatibility.

The current immutable Windows image was selected through the existing bootstrap
and launched visibly with its normal frontend ready, without a debugger port.
It differs from the menu-QA image only by the Sequence key guard; current browser
tests cover that guard. Earlier own Windows drag/playback/native-file QA remains
valid for its named image. This is not a final-image native gesture or original
4.3.26 acceptance claim. Packaged Linux lifecycle and macOS native acceptance
remain open. No new original editor comparison was performed.

Full Spine 4.3.26 project/runtime compatibility remains open. Runtime mixing,
direct binary-project loading, texture atlases, arbitrary skins/inheritance,
Path constraints and complete original numerical/Physics parity are not claimed.
Simulation remains bounded to 120 seconds. Advanced timing/Graph work, mixing and
onion skin remain part of the full animation roadmap.

Only artifacts actually attached to this release are downloadable deliverables.
Internal Windows workspace launchers, reference tools and private research are
excluded. See the [checkpoint](https://github.com/Malasuerte94/FBones/blob/v0.9.4-beta.5/docs/STATE.md),
[roadmap](https://github.com/Malasuerte94/FBones/blob/v0.9.4-beta.5/docs/ROADMAP.md)
and [contributor guide](https://github.com/Malasuerte94/FBones/blob/v0.9.4-beta.5/CONTRIBUTING.md).
