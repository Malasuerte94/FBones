# FBones v0.10.0-beta.1 — MCP first

This beta adds an AI connection to the same native Session used by the editor.
Open **MCP** next to File, start the local server and copy its configuration into
an MCP client. The connection address and token are remembered between restarts;
Start remains explicit, and Reset replaces the credentials while stopped.

- Typed tools cover the existing bones, attachments, mesh topology, auto trace,
  binding/weights, constraints/Physics, animation keys/events, resource import,
  runtime export and revision-checked binary persistence.
- The AI can read project state and schemas, receive PNG/WAV content, and request
  an actual viewport image with camera and document identity metadata.
- Native revisions, frozen pose epochs, Undo/Redo and file/resource guards apply
  to AI edits. The editor clearly indicates AI control and suspends manual edits
  until Stop refreshes the final state.
- The [AI guide](../MCP.md) and [contributor workflow](../../CONTRIBUTING.md#mcp-first)
  establish MCP first: supported operations enter the shared native API and stay
  accessible through both UI and MCP. An optional Node stdio bridge serves clients
  without direct Streamable HTTP.
- Bounded Scene mesh capacity now supports up to 1024 vertices, with context-specific
  triangle/edge/binding reader limits and independent aggregate/resource guards.
  The real showcase project retains its complete 715,855-byte payload and all 14
  animations without dropping records. Legacy, Clip and Trace limits are unchanged.
- Flat RGB8 Normal RAW/PackBits PSD import preserves supported layer positions,
  stacking, opacity and visibility in one native history action. Broader PSD
  compositing formats are still refused rather than silently changed.

The native Linux acceptance uses an independent official MCP SDK client against
a dedicated actual GTK editor window. It exercises tool discovery, native edits,
trace/weighted mesh/Physics/animation, source media, viewport images and portable
binary/resource Save/Close/Open, then verifies visible editor state, Stop and
normal native exit. The release workflow also runs normal three-platform builds,
native/unit tests, production-CSP UI checks, source/package checks and updater
signature/version gates before publishing assets.

FBones remains early beta. MCP exposes the current supported editing profiles;
it does not add a claim of full Spine compatibility or exact proprietary solver
parity. Unknown records stay inspection-only. Existing final-pass Physics,
Transform and platform-native UX limitations remain recorded in the roadmap.
The viewport tool captures the current editor view; a native evaluate request
alone does not seek that view. Actual Windows/macOS AI-client gestures are not
inferred from Linux acceptance or platform compilation.

No original editor binaries or private source projects are distributed. README
captures use a real user-authorized project, with original files and raw artwork
kept outside Git and release archives. Original artwork retains its own rights.
